# CHANGELOG 0.6.0

## 主要更新

### Bridge 子包重构：统一编译模式与编译追踪

对 `vools.bridge` 子包进行核心架构重构，引入 `CompileMode` 枚举、`CompileTracker` 编译追踪器和 `LangType` 语言类型枚举，统一所有语言桥接的编译和执行行为。

#### CompileMode 编译模式枚举

新增 `CompileMode` 枚举（`vools.bridge.core.types`），定义 7 种编译模式：

| 模式 | 常量 | 说明 |
|------|------|------|
| 正常模式 | `CompileMode.NORMAL` | 命中缓存跳过编译；未命中则编译并执行 |
| 调试模式 | `CompileMode.DEBUG` | 强制重新编译并执行 |
| 强制模式 | `CompileMode.FORCE` | 强制重新编译但**不执行** |
| 仅运行模式 | `CompileMode.ONLY_RUN` | 只在有缓存时执行；没有缓存则报错 |
| 仅代码模式 | `CompileMode.ONLY_CODE` | 只生成源码，不编译 |
| 变更编译 | `CompileMode.WHEN_CHANGE_JUST` | 检测到代码变更时编译，不执行 |
| 变更编译运行 | `CompileMode.WHEN_CHANGE_AND_RUN` | 检测到代码变更时编译并执行 |

提供辅助方法：
- `CompileMode.normalize(mode)` — 规范化模式字符串（大小写不敏感）
- `CompileMode.is_change_aware(mode)` — 判断是否为变更感知模式
- `CompileMode.is_force_recompile(mode)` — 判断是否需要强制重编译
- `CompileMode.should_execute(mode)` — 判断编译后是否需要执行

#### CompileTracker 编译记录追踪器

新增 `CompileTracker` 类（`vools.bridge.core.tracker`），基于 SQLite 数据库管理编译记录：

- **编译记录持久化**：记录每次编译的源码 MD5、编译产物路径、编译耗时、语言类型等
- **代码变更检测**：`is_changed(record_key, source_md5)` 对比源码 MD5 判断变更
- **WHEN_CHANGE 模式支持**：为 `WHEN_CHANGE_JUST` / `WHEN_CHANGE_AND_RUN` 提供底层变更检测
- **错误日志**：`compile_errors` 表记录编译失败信息
- **语言注册表**：`language_registry` 表记录语言编译器信息

数据库位置：
- Windows: `%LOCALAPPDATA%/vools/bridge_records.db`
- Linux/macOS: `~/.local/share/vools/bridge_records.db`

全局单例通过 `get_tracker()` 获取。

#### LangType 语言类型枚举

新增 `LangType` 枚举（`vools.bridge.core.types`），定义 5 种语言类型：

| 类型 | 常量 | 说明 |
|------|------|------|
| 编译型 | `LangType.COMPILED` | 编译为原生动态库（C, Rust, Nim, Go 等） |
| 解释型 | `LangType.INTERPRETED` | 打包为 zip 并通过解释器执行（Python, Ruby, Lua 等） |
| JVM | `LangType.JVM` | 编译为 JAR 包（Java, Scala, Kotlin） |
| .NET | `LangType.DOTNET` | 编译为 .NET 程序集（C#） |
| BEAM | `LangType.BEAM` | 编译为 BEAM 字节码（Erlang, Elixir） |

#### LangBridge 核心增强

`LangBridge` 抽象基类（`_base.py`）新增以下核心内部方法：

- **`_should_compile(mode, code, func) -> bool`** — 根据 `CompileMode` 和代码变更统一决策是否需要编译
- **`_compile_or_package(code, func_name, cache_dir) -> str`** — 编译型调用 `compile_code()`，解释型调用 `_package_code()`
- **`_call_or_execute(lib_path, func_name, args, ret_type) -> Any`** — 编译型调用 `call_func()`，解释型调用 `_execute_code()`
- **`_record_compile(func, code, lib_path, mode, duration_ms)`** — 记录编译信息到 SQLite 数据库
- **`_get_tracker() -> CompileTracker`** — 获取编译追踪器单例（懒加载）

新增可重写属性：
- `is_compiled -> bool` — 是否为编译型语言（默认 `True`）
- `lang_type -> str` — 语言类型（默认 `LangType.COMPILED`）
- `_package_code(code, func_name, cache_dir) -> str` — 解释型语言打包代码（默认 zip）
- `_execute_code(package_path, func_name, args, ret_type) -> Any` — 解释型语言执行代码（默认抛出 NotImplementedError）

### ⚠️ 破坏性变更

#### `only_code` 参数已废弃，改用 `mode` 参数

**旧写法（v0.5.x）：**

```python
@bridge.decorator(only_code=True, output_file="out.bas")
def hello(name: str) -> str:
    return "..."
```

**新写法（v0.6.0+）：**

```python
from vools.bridge import CompileMode

@bridge.decorator(mode=CompileMode.ONLY_CODE, output_file="out.bas")
def hello(name: str) -> str:
    return "..."
```

#### `decorator()` 签名变更

`decorator()` 方法新增 `mode` 参数（位于第一个关键字参数位置），移除 `only_code` 参数：

```python
# v0.6.0 新签名
def decorator(self, func=None, *, mode=CompileMode.NORMAL, deps=None, ...):
```

### 迁移指南

#### 1. 替换 `only_code=True`

```diff
- @bridge.decorator(only_code=True, output_file="out.bas")
+ from vools.bridge import CompileMode
+ @bridge.decorator(mode=CompileMode.ONLY_CODE, output_file="out.bas")
```

#### 2. 使用新模式

```python
from vools.bridge import CompileMode

# 调试模式 — 强制重编译并执行
@bridge.decorator(mode=CompileMode.DEBUG)
def debug_func(x: int) -> int:
    return "..."

# 强制编译（不执行） — CI/CD 预编译
@bridge.decorator(mode=CompileMode.FORCE)
def prebuild_func(x: int) -> int:
    return "..."

# 仅运行 — 生产环境
@bridge.decorator(mode=CompileMode.ONLY_RUN)
def prod_func(x: int) -> int:
    return "..."

# 变更感知（仅编译）
@bridge.decorator(mode=CompileMode.WHEN_CHANGE_JUST)
def ci_func(x: int) -> int:
    return "..."

# 变更感知（编译并执行）
@bridge.decorator(mode=CompileMode.WHEN_CHANGE_AND_RUN)
def dev_func(x: int) -> int:
    return "..."
```

#### 3. 模式字符串兼容

`CompileMode.normalize()` 支持大小写不敏感的字符串输入，代码中可以使用字符串：

```python
@bridge.decorator(mode='debug')         # 等价于 CompileMode.DEBUG
@bridge.decorator(mode='only_code')     # 等价于 CompileMode.ONLY_CODE
@bridge.decorator(mode='when_change_just')  # 等价于 CompileMode.WHEN_CHANGE_JUST
```

#### 4. 编译记录查询

```python
from vools.bridge import get_tracker

tracker = get_tracker()
record = tracker.get_record('mymodule:my_func')
if record:
    print(f"上次编译: {record['compiled_at']}")
    print(f"编译耗时: {record['compile_duration_ms']}ms")
    print(f"编译模式: {record['compile_mode']}")
```

### 桥接编译器修复

#### 解释型语言桥接修复

- **PowerShell 桥接**：重写 `_execute_code()` 方法，支持参数传递（JSON 序列化）、函数调用和输出解析，12 个测试全部通过
- **Shell 桥接**：修复 5 个 bug — 参数传递、WSL 路径转换（`/mnt/c/...`）、`\r\n` 行尾问题、Python 3.6 兼容性（`capture_output`/`text` 参数）、返回类型自动检测，10 个测试全部通过
- **VBScript 桥接**：重写 `_execute_code()` 方法，利用 `_generate_vbs_source()` 构建完整可执行脚本（含 JSON 参数解析和结果序列化），12 个测试全部通过
- **TypeScript 桥接**：修复模板生成（函数包裹在 `function` 中）、重写 `_execute_code` 使用 stdin/stdout JSON 协议替代 `require()`，13 个测试全部通过

#### 编译型语言桥接修复

- **C 桥接**：修复 `_get_c_path()` 回退到可用 gcc（CodeArts MinGW 同目录），修复 `call_func()` 返回值类型映射，31 个测试全部通过
- **C++ 桥接**：修复 `_generate_cpp_wrapper()` 类型映射键类型不匹配（类对象 vs 字符串），浮点参数不再被错误声明为 int，31 个测试全部通过
- **Nim 桥接**：移除 MSVC 不兼容的 `--passL:-Wl,--export-all`，改用 `/EXPORT:` 链接器标志；`cbool` → `bool` 适配 Nim 2.2.10；修复 `call_func()` 返回类型映射，23 个测试全部通过
- **Go 桥接**：安装 Go 1.26.5 + MinGW GCC 16.1.0；修复 cgo 类型严格转换（`C.longlong()`）、`unsafe` 导入按需添加、管理器版本检查传递 `version_args`，29 个测试全部通过
- **Scala 桥接**：修复 `.bat` 文件查找（`shutil.which()`）、JAR 打包（`scalac` → `jar`）、`lib_ext` 纠正为 `.jar`、执行方案改为 `scala -e` 直接运行，12 个测试全部通过
- **VB.NET 桥接**：更新模板目标框架为 `net9.0`、修复 `dotnet build` 参数（移除 `-o`）、重写 `save_to_cache()` 和 `check_cache()` 方法，28 个测试全部通过
- **Zig 桥接**：修复 `_generate_function()` 双重 `return` 语句、添加 `--global-cache-dir` 独立缓存目录、适配 Zig 0.16 语法（`@rem` 替代 `%`），23 个测试全部通过

#### 并发竞态修复

- **`_package_code()` 原子写入**：使用 `tempfile.mkstemp` + `os.replace` 原子性替换 zip 文件，添加双重检查（double-checked locking）避免并发读取半写入文件
- **`save_to_cache()` 原子重命名**：`shutil.copy2` → `os.replace` 避免缓存目录出现重复文件
