# 实现指南

## 概述

本文档详细说明 Scala、Kotlin、Nim 三种语言中隐式双元操作符的实现差异与使用方法。

## 语言特性差异

### Scala

- 原生支持特殊符号作为方法名（如 `#>`, `<#`, `~>`, `|>`）
- 通过 `implicit class` 为任意类型添加扩展方法
- 支持中缀调用语法：`left op right`
- 类型推断能力强，函数组合时类型自动推导

### Kotlin

- 不支持 `<` 和 `>` 作为方法名开头
- 通过 `operator fun` 定义操作符
- 使用反引号包裹特殊名称：`` `#gt` ``
- 扩展函数语法：`fun Type.op(param): Result`

### Nim

- 使用 ASCII 命名的过程（proc）
- 通过 `exportc` 导出 DLL 函数
- 支持函数类型和闭包
- 使用 `--app:lib` 编译为动态链接库

## Scala 实现详情

### 核心机制

Scala 使用 `implicit class` 为函数类型添加扩展方法：

```scala
implicit class Function0Compose01Forward[A](f: () => A) {
  def #>[B](g: A => B): () => B = () => g(f())
}
```

### 导入方式

```scala
import com.example.operators.Operators._
```

### 注意事项

- 本实现已移除 `scala.collection.BuildFrom` 依赖，兼容 Scala 2.11.x
- 集合操作符返回 `Iterable[B]`，而非保持原始集合类型
- 解包操作符支持 TupleN（编译期解包）和 Seq（运行期取首元素）

## Kotlin 实现详情

### 核心机制

Kotlin 使用 `object` 定义操作符容器，通过扩展函数和成员函数实现：

```kotlin
object Operators {
  operator fun <A, B> (() -> A).`#gt`(g: (A) -> B): () -> B = { g(this()) }
  fun <A, B> pipe(value: A, f: (A) -> B): B = f(value)
}
```

因 Kotlin 语法限制，操作符名称做了如下映射：

| 原始名称 | Kotlin 名称 | 说明 |
|----------|-------------|------|
| `#>` | `#gt` | greater than |
| `<#` | `lt#` | less than |
| `#>>` | `#gtgt` | greater than greater than |
| `<<#` | `ltlt#` | less than less than |
| `*#>` | `star#gt` | star greater than |
| `<#*` | `lt#star` | less than star |
| `~>` | `tildegt` | tilde greater than |
| `<~` | `lttilde` | less than tilde |
| `~>>` | `tildegtgt` | tilde greater than greater than |
| `<<~` | `ltlttilde` | less than less than tilde |
| `*~>` | `startildegt` | star tilde greater than |
| `<~*` | `lttildestar` | less than tilde star |
| `~~>` | `tildetildegt` | tilde tilde greater than |
| `<~~` | `lttildetilde` | less than tilde tilde |
| `*~~>` | `startildetildegt` | star tilde tilde greater than |
| `<~~*` | `lttildetildestar` | less than tilde tilde star |
| `~~>>` | `tildetildegtgt` | tilde tilde greater than greater than |
| `<<~~` | `ltlttildetilde` | less than less than tilde tilde |
| `\|>` | `pipe` | pipe |
| `<\|` | `pipeLt` | pipe left |
| `\|>>` | `pipeMap` | pipe map |
| `<<\|` | `pipeMapLt` | pipe map left |
| `\|?>` | `pipeFilter` | pipe filter |
| `<\|?` | `pipeFilterLt` | pipe filter left |
| `\|*>` | `pipeFlatMap` | pipe flatMap |

| `<&\|` | `pipeReduceLt` | pipe reduce left |
| `\|@>` | `pipeFold` | pipe fold |
| `<@\|` | `pipeFoldLt` | pipe fold left |

### 使用示例

```kotlin
import com.example.operators.Operators._

fun genA(): String = "Hello"
fun genB(s: String): String = "$s, World!"

val merged = genA `#gt` genB
println(merged())

val doubled = listOf(1, 2, 3).pipeMap { it * 2 }
println(doubled)
```

## Nim 实现详情

### 核心机制

Nim 使用过程（proc）和模板（template）实现操作符：

```nim
proc compose01[A, B](f: proc(): A, g: proc(x: A): B): proc(): B =
  result = proc(): B = g(f())

proc pipe[A, B](value: A, f: proc(x: A): B): B =
  result = f(value)
```

### DLL 导出

使用 `exportc` 标记导出函数：

```nim
proc pipeInt(f: proc(x: int): int, value: int): int {.exportc, dynlib.} =
  result = f(value)
```

### 操作符名称映射

| 原始名称 | Nim 名称 | 说明 |
|----------|----------|------|
| `#>` | `compose01` | 无参函数 → 单参函数 |
| `<#` | `compose01Rev` | 反向 |
| `#>>` | `compose02` | 无参函数 → 双参函数 |
| `~>` | `compose11` | 单参函数 → 单参函数 |
| `~>>` | `compose12` | 单参函数 → 双参函数 |
| `~~>` | `compose21` | 双参函数 → 单参函数 |
| `~~>>` | `compose22` | 双参函数 → 双参函数 |
| `\|>` | `pipe` | 值 → 函数 |
| `\|>>` | `pipeMap` | 可迭代 → map |
| `\|?>` | `pipeFilter` | 可迭代 → filter |
| `\|*>` | `pipeFlatMap` | 可迭代 → flatMap |
| `\|&>` | `pipeReduce` | 可迭代 → reduce |
| `\|@>` | `pipeFold` | 可迭代 → fold |

### 使用示例

```nim
import operators

proc genA(): string = "Hello"
proc genB(s: string): string = s & ", World!"

let merged = compose01(genA, genB)
echo merged()

let doubled = pipeMap(@[1, 2, 3], proc(x: int): int = x * 2)
echo doubled
```

## 性能考量

### Scala

- 隐式类在编译期展开，运行时无额外开销
- 函数组合返回新函数，懒求值
- 集合操作符直接调用 `Iterable.map/filter`，性能与标准库一致

### Kotlin

- 扩展函数编译为静态方法调用
- Lambda 表达式有轻微运行时开销
- 集合操作符使用标准库方法，性能与标准库一致

### Nim

- 过程调用开销极低
- 编译期优化消除大部分间接调用
- DLL 导出函数有额外的调用开销

## 扩展建议

### 添加新操作符

1. 在 Scala 中添加 `implicit class` 和扩展方法
2. 在 Kotlin 中添加扩展函数或成员函数
3. 在 Nim 中添加 proc 和 DLL 导出

### 性能优化

1. Scala：使用 `@inline` 注解内联简单操作符
2. Kotlin：使用 `inline` 修饰符内联 Lambda
3. Nim：使用 `{.inline.}` pragma 内联过程

### 类型安全增强

1. Scala：使用更精确的类型约束
2. Kotlin：使用泛型约束和 `reified` 类型参数
3. Nim：使用 `{.experimental: "strictFun".}` 启用严格函数类型

## 常见问题

### Q: Scala 编译时找不到符号？

A: 确保已导入 `Operators._`：

```scala
import com.example.operators.Operators._
```

### Q: Kotlin 中操作符名称报错？

A: 使用反引号包裹特殊名称：

```kotlin
val result = genA `#gt` genB  // 正确
val result = genA #gt genB    // 错误
```

### Q: Nim DLL 无法加载？

A: 确保 DLL 文件与可执行文件在同一目录，或正确设置 PATH。

### Q: Scala 2.11.x 兼容性问题？

A: 本实现已移除 `BuildFrom` 依赖，直接使用 `Iterable` 方法，兼容 Scala 2.11.x。
