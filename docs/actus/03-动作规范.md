## 1. 三层动作边界

动作按"谁分发、谁扫描"分三层，索引时**用户项目优先于基座种子**：

```
┌─────────────────────────────────────────────┐
│ 第 1 层：基座种子动作（随 wheel 分发）          │
│   vools/actus/actions/**/*.actus.md          │
│   vools/actus/actions/**/*.actus.schema.md   │
│   → pip install vools-actus 即有 4 个 GUI 基线动作 │
├─────────────────────────────────────────────┤
│ 第 2 层：用户项目动作（Git 仓，索引优先）        │
│   <ACTUS_REPO_ROOT>/actions/**               │
│   → 同名 id 冲突时用户项目胜出（索引排后者）      │
├─────────────────────────────────────────────┤
│ 第 3 层：社区仓动作（curator 发现）             │
│   curator.list_default_repos() 指向的远程 Git 仓 │
│   → 策展是推荐不是门槛（不封闭审核）             │
└─────────────────────────────────────────────┘
```

**扫描根解析**（`indexer._action_roots`）：显式传 `actions_dir` 只扫该目录
（测试/单仓场景）；缺省 = 用户项目 actions/ + 包内种子目录（去重保序）。

**文件后缀双轨**（`indexer.ACTION_SUFFIXES`）：

| 后缀 | 元数据形态 | 状态 |
|------|-----------|------|
| `.actus.schema.md` | YAML front-matter | **新格式（推荐）** |
| `.actus.md` | `#!cfg` JSON 内联块 | 旧格式（向后兼容） |

两种后缀都进索引、都过同一套 validate 管线。

## 2. 分类体系 v2.0

单一真源：`vools.actus.constants`（`KIND_LEVELS` 等），schema 投影：
`contracts/action.schema.json`。版本：`CLASSIFICATION_VERSION = '2.0'`。

### 2.1 五维度

| 维度 | 字段 | 单值/多值 | 必填 | 默认 | 未知值行为 | 回答的问题 |
|------|------|----------|------|------|-----------|-----------|
| 执行类型 | `kind` | 单值 | ✅ | 旧动作回填 `exec` | **打回** | 怎么执行？ |
| 用途 | `purpose` | 多值 1..5 | 可选 | `[utility]` | **警告** | 做什么？ |
| 行业 | `industry` | 多值 1..5 | 可选 | `[general]` | **警告** | 服务谁？ |
| 触发声明 | `trigger` | 多值 1..8 | 可选 | `[manual]` | **警告** | 怎么被唤起？ |
| 适用上下文 | `context_applies` | 多值 0..10 | 可选 | `[]` | **警告** | 在哪些软件/文件/OS 场景？ |

**为什么 kind 未知值打回、其余警告**：kind 决定系统如何执行
（exec/link/demo/template/alias/bundle/doc），错误值导致执行逻辑混乱；
其余是分类标签，不影响执行，未知值只影响索引覆盖——开放枚举支持未来扩展
（新值追加到 constants 元组即生效，已入库动作立即受益）。

**多值即跨维度**：`purpose: [transform, ai]` 表示"既是转换又是 AI"，
`industry: [general, devops]` 表示"通用 + DevOps 专用"。

### 2.2 已知值集合

```python
KIND_LEVELS         = ('exec', 'link', 'demo', 'template', 'alias', 'bundle', 'doc')
PURPOSE_LEVELS      = ('source', 'sink', 'transform', 'orchestrator', 'notify',
                       'control', 'monitor', 'compute', 'ai', 'data-store',
                       'security', 'utility')
INDUSTRY_LEVELS     = ('devops', 'finance', 'healthcare', 'hr', 'sales',
                       'marketing', 'customer-support', 'education', 'legal', 'general')
TRIGGER_DECL_LEVELS = ('manual', 'cron', 'watch', 'webhook', 'hotkey',
                       'on_startup', 'signal', 'dataset')
```

`context_applies` **不设闭集**——自由字符串（Quicker 式：exe 名/文件类型/OS），
如 `context_applies: ["chrome.exe", "explorer.exe", "*.md"]`。

### 2.3 kind × purpose 语义冲突（警告级）

| 组合 | 判定 |
|------|------|
| `kind: doc` + `purpose: [source/compute/...]` | 警告：纯文档不应声明执行用途 |
| `kind: template` + `purpose: [orchestrator]` | 警告：模板不编排 |
| `kind: link` + `purpose: [transform]` | 合法（链接转发转换动作） |

### 2.4 验证分级表

| 级别 | 行为 | 适用 |
|------|------|------|
| 必填 | 缺失 → 打回 | `id`, `name`, `version`, `trust`, `kind` |
| 可选+默认 | 缺失 → 用默认值 | `purpose`/`industry`/`trigger`/`license`/`pricing` |
| 警告 | 未知值 → 警告但接受 | 五维度中除 kind 外的未知值、`license` 未知、`demo` 缺失文件 |
| 打回 | 非法值 → 拒绝 | `kind` 未知、`trust` 非法、`id` 不合反域名规范 |

消费入口：`validate_action`（打回级）+ `classification_notices`（警告级）。

### 2.5 多值标准化

`validate.normalize_multi_field(values, known_levels, max_n)`：
小写归一 → 去重 → 按 max_n 截断（追加截断警告）→ 已知值/未知值分离
（未知值保留不丢弃，前向兼容）。

### 2.6 索引与查询

`_meta/actions.index.json`（schema_version 2.0.0）含：

```
actions:      {action_id: brief}          # brief 带 kind/purpose/industry/md5/...
by_kind:      {kind: [action_id...]}
by_purpose:   {purpose: [action_id...]}
by_industry:  {industry: [action_id...]}
by_name:      {name_lower: [action_id...]}  # ACTUS_REFACTOR_PLAN §3.5：按人类可读名查索引
by_md5:       {md5_32hex: action_id}        # ACTUS_REFACTOR_PLAN §3.5：按内容 MD5 指纹查索引
```

```python
from vools.actus import filter_by_dimension
filter_by_dimension('purpose', 'control')   # → ['actus.basics.calculator', ...]
```

**索引扩展（ACTUS_REFACTOR_PLAN §3.5）**：

| 反向索引 | 键 | 值形态 | 语义 |
|---------|-----|--------|------|
| `by_name` | `brief.name` 小写归一 | `[action_id, ...]` | 多命中保留全部，resolver 报 ambiguous |
| `by_md5` | `brief.md5`（32 位 hex） | `action_id`（单值） | 内容指纹唯一，resolver 按指纹定位 |

`by_name` / `by_md5` 在 `build_index` 时一次性构建，落盘 `_meta/actions.index.json`。旧索引缺这两个键时 resolver 按现有 `actions` 字典回退查 `brief.md5` / `brief.name`，不破坏兼容。

## 4. 生态层

### 4.1 使用量指标（`calllog.action_metrics`）

执行计数（**非安装计数**——Quicker 经验：只有执行计数能区分"安装了"
vs"真正在用"）：

```python
from vools.actus import aggregate_metrics, popular_actions, trending_actions

aggregate_metrics('actus.basics.calculator')
# → {total, last_7d, last_30d, success_rate, avg_runtime_ms, unique_callers}
popular_actions(limit=10)     # 按执行计数 top-N
trending_actions(limit=10)    # 按 7 日相对 30 日增长率
```

### 4.2 质量分级（`quality.quality_scale`，借鉴 HA Quality Scale）

**计算字段，非手工申报**（杜绝自写自测恒绿）：

| 等级 | 判据 |
|------|------|
| `platinum` | 已签名 + Omega spec + 100+ 执行 + 99% 成功率 + 30 天内维护 |
| `gold` | 已签名 + Omega spec + 50+ 执行 + 95% 成功率 |
| `silver` | 已签名 + 10+ 执行 + 90% 成功率 |
| `bronze` | 任意执行（默认） |
| `internal` | 引擎/系统动作 |

```python
from vools.actus import quality_scale
quality_scale(action)   # → {quality, evidence: {...}}
```

### 4.3 许可证与定价

三层模型：`trusted`(核心, Apache-2.0, 免费) / `community`(作者选, 免费) /
`gated`(专有, 可付费)。`gated` 复用 `visibility.GatedKeyStore`；
**当前版本未接支付通道**，`pricing: paid` 按 gated 免费放行 + 警告（预留）。

### 4.4 社区策展（`curator`）

策展是**推荐不是门槛**（避免 Zapier 式封闭审核杀社区贡献）：

```python
from vools.actus import (
    add_default_repo, list_default_repos,          # 默认仓（HACS 式）
    create_collection, share_collection,            # 集合（Quicker 动作单）
    get_featured,                                   # 精选（popular ∩ trending）
)
```

## 6. 多形态目标与入参（ACTUS_REFACTOR_PLAN §3.1 / §3.2）

> 状态：**已实施** · 2026-10-21

### 6.1 任意语言入口

入口块语言标记不再限定 Python。所有在 `vools.bridge.md.runner.known_languages()` 注册的语言均可作为入口：

| 类别 | 语言标记 | 运行时 |
|------|---------|--------|
| 脚本 | `python` / `py`、`shell` / `bash` / `sh`、`powershell` / `pwsh`、`cmd`、`bat` | runtimes.py 内置 |
| 编译型 | `node` / `js`、`go` / `golang`、`rust` / `rs`、`ruby` / `rb`、`php` | runtimes.py 内置 |
| 桥接 | `typescript` / `ts`、`zig`、`nim`、`perl`、`lua`、`r` 等（`vools/bridge/<lang>/compiler.py`） | BridgeManager 自动发现 |

**校验规则**（`validate.check_block_languages`）：
- 入口块语言必须在 `known_languages()` 注册集内，否则 verify 报错
- `is_routable()` 只判标记注册，不判编译器安装；可用性由执行期 `is_available()` 显式报不可用
- kind ≠ exec 时入口豁免（link/demo/template/alias/bundle/doc 无源码或演示模式）

### 6.2 目标解析器（resolver.py）

`actus run <target>` 支持六种形态，首命中即返回：

| 优先级 | 形态 | 示例 |
|--------|------|------|
| 1 | 本地零散路径 | `./actions/foo.actus.md`、`./lib/foo.actus/` |
| 2 | 动作 id（反域名） | `actus.cli.jq` |
| 3 | 32 位 hex 指纹（MD5） | `9f2c…` → 查 `by_md5` |
| 4 | http/https URL 动作源 | `https://…/foo.actus.md`（需 `--allow-host` 白名单） |
| 5 | 按 name 查索引 | `bench_polyglot` → 查 `by_name` |
| 6 | 回退尝试 id | 含点串按 id 路径报错附候选 |

解析结果 `ResolvedTarget`：`source` / `action_id` / `path` / `raw` / `ambiguous` / `url` / `downloaded`。

### 6.3 入参解析器扩展

`actus run <target> <jsonexpr>` 入参支持六种形态：

| 形态 | 示例 |
|------|------|
| JSON 字面量 | `'{"a":1}'` |
| 本地 JSON 文件 | `@args.json` |
| stdin | `-` |
| JSON URL | `@https://…/args.json`（需 `--allow-host` 白名单，5 MiB 上限，30s 超时） |
| 动作引用 | `@action:<action_id>`（递归深度默认 3，循环检测，取其出参作入参） |

## 7. 索引扩展（ACTUS_REFACTOR_PLAN §3.5）

`_meta/actions.index.json` 新增反向索引：

| 反向索引 | 键 | 值形态 | 构建来源 |
|---------|-----|--------|---------|
| `by_name` | `brief.name` 小写归一 | `[action_id, ...]` | `build_index` 扫描 `entries` |
| `by_md5` | `brief.md5`（32 位 hex） | `action_id`（单值） | `build_index` 扫描 `entries` |

**向后兼容**：旧索引缺 `by_name` / `by_md5` 时，resolver 按 `actions` 字典回退查 `brief.md5` / `brief.name`，不破坏旧版索引读取。

分层抽象（借鉴 WoT affordance + MCP capability negotiation + n8n Node SDK）：

```
统一接口层：ActionExecutor.execute(action, ctx) → ExecResult    ← exec_iface
协议绑定层：CLI / MCP / HTTP / Quicker 适配                      ← adapter
实现层：runner / runtimes / scattered                            ← 现有执行管线
```

- `ExecutionContext`：params / caller / capabilities（按请求协商）/ env / timeout_ms / dry_run
- `ExecResult`：status(ok/error) / data / error / error_kind / duration_ms / artifacts
- `error_kind` 闭集：auth / quota / unreachable / invalid / timeout / resource / runtime
- `executor.py` 的 `error.code`（auth_required/param_invalid/...）经 `_ERROR_CODE_MAP`
  映射到闭集，未知码兜底 runtime

新增执行通道只需实现 `execute()`，消费方（CLI/MCP/workflow）不变。
